# 独立商业化架构

## 目标

Superstaff 的基础版本必须在没有云模型、云视频和平台发布授权的情况下完成主要业务闭环。第三方能力只能作为客户主动启用的适配器，不能成为产品启动条件。

```text
React 工作台
    ↓ REST API
FastAPI 业务服务 ── SQLite 本地数据
    ├── 内置规则执行器（始终可用）
    ├── Ollama + Qwen3（可选、本地）
    ├── Canvas / MediaRecorder / Web Audio（本地视频）
    └── 人工审核发布包（不需要平台 OAuth）
```

## 为什么不把 Dify 嵌入商业核心

用户已有的 `dify-rag-portfolio` 提供了可靠的 Ollama 网络隔离、模型下载和健康检查经验，可以复用这些部署思路。但 Dify 本身采用带附加条件的修改版 Apache-2.0 许可证，对多租户服务和前端 Logo 修改设置了商业许可条件。因此 Superstaff 直接调用 MIT 许可的 Ollama API，不复制 Dify 前端或运行时。

## 许可证原则

“不需要第三方商业授权”表示无需联系厂商购买授权或签署单独商务合同，并不表示可以忽略开源许可证。商业构建只接受：

- MIT、BSD、Apache-2.0、PSF 等宽松许可证，以及经审计、按文件履行义务的 MPL-2.0 组件；
- 经过单独审计且允许商业分发的模型、声音、字体和媒体资产；
- 客户自行提供并自行承担合同关系的可选云服务。

不默认捆绑来源不明的音色、音乐、图库、字体和模型权重。

## 无法绕过的外部边界

- 自动发布到抖音、小红书、视频号等平台必须获得官方授权；基础版只导出发布包。
- 写实生成式视频的质量取决于基础模型和算力；基础版专注稳定、可控的品牌内容视频。
- 模型运行时的许可证不自动覆盖模型权重，语音引擎许可证也不自动覆盖音色数据。

## 商业产品分层

1. 标准本地版：规则执行器、工作流、资产、视频模板、人工导出。
2. 本地 AI 版：增加 Ollama + Qwen3，用于真实规划、写作和分镜。
3. 企业私有部署版：增加登录权限、备份恢复、审计、品牌定制和维护服务。
4. 可选连接器：客户自有云模型、素材库或平台 OAuth，独立报价和授权。
