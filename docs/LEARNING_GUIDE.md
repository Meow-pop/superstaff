# 跟着超级 AI 员工项目学习软件工程

你的起点不是“完全不会编程”，而是会用 Python 和 MATLAB 完成科研计算，但还没有把程序做成别人可以使用和维护的软件。我们会在复现视频中超级员工系统的过程中补上这段距离。

这里必须分清主次：产品仍然按照参考视频建设；学习发生在阅读代码、修改功能、运行测试和复盘架构的过程中，不会把产品改造成教学平台。

## 学习原则

不追求你立刻脱离 AI 手写整个系统。分三个阶段：

1. **看得懂**：知道一个文件属于哪一层，重要代码在做什么。
2. **改得动**：能改字段、样式、校验规则或一个简单接口，并验证结果。
3. **讲得清**：能解释一次请求如何从浏览器到数据库，再把结果返回页面。

每次新增功能都按同一条路径学习：

```text
页面操作 → 浏览器请求 → FastAPI 路由 → Service 业务逻辑
        → Repository 数据读写 / Executor AI 执行 → JSON 响应 → 页面更新
```

## 先认识本项目里的技术

| 技术 | 在本项目中做什么 | 你当前需要掌握到什么程度 |
| --- | --- | --- |
| HTML | 提供网页入口和元素结构 | 能认出标签和表单 |
| CSS | 控制布局、颜色、间距和响应式 | 能用浏览器检查并改常见样式 |
| JavaScript | 让网页响应点击并请求接口 | 理解变量、函数、异步请求 |
| TypeScript | 给 JavaScript 数据加类型约束 | 能读接口类型和编译错误 |
| React | 用组件和状态组织复杂界面 | 理解组件、props、state、effect |
| Python | 实现后端业务和 AI 调用 | 从脚本提升到包、类、异常和测试 |
| FastAPI | 把 Python 功能暴露成 HTTP API | 能新增一个路由并读懂请求模型 |
| SQL / SQLite | 持久保存员工、任务和成果 | 会基本增删改查和表关系 |
| pytest | 自动验证程序没有被改坏 | 能读测试并补一个正常/异常用例 |
| Git | 记录和协作代码变更 | 会看 diff、提交、分支和回退概念 |

## 第一课：追踪“创建任务”

完成正式骨架后，按下面顺序阅读，不要从第一行开始硬啃整个仓库：

1. 在前端找到“创建任务”按钮和提交函数。
2. 在浏览器开发者工具 Network 中找到 `POST /api/v1/jobs`。
3. 在后端路由找到同名地址。
4. 看路由如何调用 `JobService.create_job()`。
5. 看 Service 如何调用执行器生成计划，再调用 Repository 保存。
6. 用 FastAPI `/docs` 手动发送一次请求。
7. 看自动化测试如何验证返回状态是 `draft`。

完成后，你应该能回答：

- 为什么前端不直接写 SQLite？
- 为什么 API 要校验输入？
- 为什么业务逻辑不全部写在路由函数里？
- 为什么任务先是 `draft`，而不是直接 `done`？

## 面试时怎么定位自己

短期不把自己包装成纯前端或资深后端，而是：

> 电力系统博士背景的 AI 应用 / 科学计算工程化研发，能够用 Python 构建后端服务，并完成基础的 React 前端和数据库闭环。

这个定位保留了电力系统、优化和科研能力，同时拿出真实软件工程证据。

## 项目讲解模板

面试官问“这个项目是怎么做的”，可以按下面顺序回答：

1. **问题**：普通聊天模型只能回答，不能持续管理业务任务。
2. **产品**：系统把 AI 封装成有角色、技能、工作流和权限的员工。
3. **前端**：React + TypeScript 负责任务下达、状态展示和人工验收。
4. **后端**：FastAPI 用分层结构管理任务状态、执行器和数据持久化。
5. **数据**：Demo 使用 SQLite，生产计划迁移 PostgreSQL 和异步队列。
6. **安全**：模型密钥在服务端，关键外部动作需要人工确认。
7. **验证**：用 API 测试覆盖创建、执行、非法状态和验收流程。

不要只说“这个项目是 AI 帮我写的”。更准确的表达是：

> 我用 AI 辅助实现和审查代码，但我负责定义产品边界、数据模型、接口契约和验收标准，并能沿着请求链路解释与修改系统。
