# 第 5 课：从“能运行”到“能交付”

这一课对应系统控制台。它解释为什么产品除了业务页面，还需要设置、诊断、审计和备份。

## 1. 工作区设置为什么属于后端

工作区名称、管理员称呼、演示模式和人工确认策略写入 `workspace_settings` 表，而不是只放在 React 状态中，所以刷新页面和重启容器后仍然存在。

```text
SystemConsolePage
  → PATCH /api/v1/workspace
  → AdminService.update_workspace()
  → SQLiteAdminRepository.save_workspace()
  → workspace_settings
```

## 2. 为什么供应商页面不展示密钥

前端只看到适配器名称、能力类别、运行模式和“是否检测到服务端凭据”。真实密钥只能通过服务器环境变量注入。

- 配置状态可以展示给管理员；
- 密钥值不能进入 API 响应、浏览器存储、Git 或日志；
- 检测到凭据也不等于调用成功，正式版还需要连通性测试。

## 3. 健康检查和诊断有什么不同

`/health` 只回答“服务进程是否活着”，适合 Docker 快速探测。`/admin/diagnostics` 还会返回版本、运行时、SQLite 状态、文件大小和业务记录数量。

## 4. 操作审计如何工作

FastAPI 中间件在成功完成 `POST`、`PATCH`、`DELETE` 后写入 `audit_events`：

```text
HTTP 请求 → 业务路由 → 成功响应 → 审计中间件 → audit_events
```

当前记录方法、路径、资源、状态码和时间，不记录请求正文，因此不会把内容、密码或密钥复制到审计表。

## 5. 为什么备份是 JSON

SQLite 文件复制适合运维人员，但 JSON 更适合检查、迁移和版本审计。导出包含格式版本、来源产品、导出时间、工作区和所有允许导出的业务表。

当前提供安全的只读导出。恢复会覆盖数据，未来应增加格式校验、预览、确认口令和事务回滚后再开放。
